# Rootfs image builder

This repo builds root filesystem images or initrd images based on Docker containers.

Note: *some assembly required.*

Images are generated by:
1. Pulling a base image from Docker Hub.
2. Installing systemd or any other init system. Alpine uses OpenRC while Amazon Linux and Ubuntu use systemd.
3. Installs sshd and other utilities to make the image usable.
4. Sets `root:root` as the default user and password.
5. Packs the docker container into a rootfs/initrd image.

See the [releases](https://github.com/gbionescu/build-rootfs/releases) page for pre-built images and kernel.

## Prerequisites

Have `docker` installed.

Cross-architecture builds also require binfmt handlers. `build-rootfs.sh` registers
them automatically with Docker when they are missing:

```bash
docker run --privileged --rm tonistiigi/binfmt --install arm,arm64,riscv64
```

## Building a rootfs

Simply run:

```bash
./build-rootfs.sh <rootfs-type>
```

Where `rootfs-type` is one of the root filesystem generators that starts with `type-`.
The default architecture is `amd64`.

For example, to generate an `alpine` rootfs, run:

```bash
./build-rootfs.sh alpine
```

Ubuntu 22.04 and 24.04 can be built for `arm64`, `arm32`, and `riscv64`:

```bash
./build-rootfs.sh ubuntu24.04 --arch arm64
./build-rootfs.sh ubuntu22.04 --arch arm32
./build-rootfs.sh ubuntu24.04 --arch riscv64
```

amd64 images are written to `rootfs.ext4`. Other architectures are written to
`rootfs_<arch>.ext4`. Use `-o <path>` to override the output path.

Notes:

- All images have ssh enabled by default.
- The default user is `root` with password `root`.
- By default, all images are generated as sparse files.
- Ubuntu images include `git`, `gcc`, `vim`, `sudo`, `ethtool`, `ping`,
  `net-tools`, OpenSSH, `udhcpc`, and `apt`, so they can be used as small
  development guests.

## Building an initrd

The initrd is built using `./build-initrd.sh`. By default it's based on the alpine image.

## Run with QEMU

Usage:

```bash
./run-qemu.sh [rootfs-image] [options]
```

The rootfs image is optional. When omitted, `run-qemu.sh` uses the same default
paths as `build-rootfs.sh`:

| Architecture | Default rootfs | Default kernel |
|--------------|----------------|----------------|
| `amd64` | `rootfs.ext4` | `kernel/bzImage-6.1.22` |
| `arm64` | `rootfs_arm64.ext4` | `kernel/Image-6.1.22-arm64` |
| `arm32` | `rootfs_arm32.ext4` | `kernel/zImage-6.1.22-arm32` |
| `riscv64` | `rootfs_riscv64.ext4` | `kernel/Image-6.1.22-riscv64` |

The default rootfs paths are the outputs of `build-rootfs.sh`; build the image
first. The kernels are [built-in to the repo](kernel/README.md). Override the
rootfs with `--rootfs <path>` or the positional argument, and the kernel with
`-k <path>` or `--kernel <path>`. Do not pass both a positional rootfs and
`--rootfs`; the script rejects the ambiguity. To build a custom kernel instead,
run `./kernel/build-kernel.sh <arch>` and pass the result with `--kernel`.

Available options:

| Option | Description |
|--------|-------------|
| `-a, --arch <arch>` | Architecture: `amd64` (default), `arm64`, `arm32`, `riscv64` |
| `-r, --rootfs <path>` | Rootfs image path (defaults per architecture above) |
| `-k, --kernel <path>` | Kernel image path (defaults per architecture above) |
| `-s, --share <dir>` | Share a host directory at `/mnt/linux-app` (default: `./linux-app`) |
| `--no-share` | Disable the default `./linux-app` share |
| `--no-net` | Disable QEMU user-mode networking |
| `--ssh-port <port>` | SSH host forward port on `127.0.0.1` (default: `2222`) |
| `-h, --help` | Show help |

Examples:

```bash
./run-qemu.sh                                  # amd64, uses rootfs.ext4
./run-qemu.sh rootfs_arm64.ext4 --arch arm64
./run-qemu.sh --arch arm64                     # uses rootfs_arm64.ext4
./run-qemu.sh --arch arm32 --rootfs rootfs_ubuntu24.04_arm32.ext4
./run-qemu.sh --arch riscv64 --kernel /path/to/Image-6.1.22-riscv64
./run-qemu.sh --rootfs /tmp/rootfs.ext4 --kernel /tmp/bzImage
```

Images built with `build-rootfs.sh -o <path>` are not at the default location;
pass them with `--rootfs <path>` or as the positional argument.

This starts a QEMU instance with:
- no KVM or graphics
- 1GB of RAM
- 1 CPU (default)
- serial console in the terminal
- user-mode networking with DHCP on `eth0`
- SSH forwarded to `127.0.0.1:2222`
- the default kernel image for the selected architecture

Emulated architectures boot much more slowly than amd64; allow several minutes for
the first boot.

The guest obtains `10.0.2.15` through `udhcpc`. Connect with:

```bash
ssh -p 2222 root@127.0.0.1
```

Use `--no-net` to disable networking and `--ssh-port <port>` to change the host
forward port.

By default, `./linux-app` is shared into the guest through 9p and auto-mounted at
`/mnt/linux-app`. Use `--share <dir>` to share another directory, or `--no-share`
to disable sharing:

```bash
./run-qemu.sh --arch arm64
./run-qemu.sh --arch arm64 --share /path/to/apps
./run-qemu.sh --arch arm64 --no-share
```

Images built before the 9p auto-mount change must be rebuilt to get the
`/etc/fstab` entry.

## Customizing the build process

Each rootfs generator consists of 3 files:

- `init-rootfs.sh`: creates the root filesystem and formats it.
This is needed because a distribution may take a larger amount of space

- `inside-container.sh`: what is installed in a rootfs.
Here this script usually finishes with copying the rootfs contents to a mounted rootfs.ext4 file.

- `run-container.sh`: controls the container lifetime and selects the Docker platform.

### Adding a new image type

Just add a new folder with the 3 files described above

### Tests

`./tests/test-all.sh` builds all amd64 rootfs types and boots them with QEMU.

`./tests/test-multiarch.sh` builds Ubuntu 24.04 for arm64, arm32, and riscv64 and
boots each image. Emulated boots are slow, so this suite takes considerably longer.

`./tests/test-arch.sh` checks the architecture mapping and CLI validation without
building an image.

`./tests/test-share.sh <image> <arch>` boots an image with the default
`linux-app` share, logs in, and verifies `/mnt/linux-app/test1/hello.c`.

`./tests/test-tools.sh <image> <arch>` boots with networking and the `linux-app`
share, then checks the installed tools, compiles `hello.c`, pings `10.0.2.2`,
runs `apt-get update`, and verifies SSH is active.

To run the amd64 tests, simply run:

```bash
./tests/test-all.sh
```

## Troubleshooting

- Need a larger image? Change `init-rootfs.sh`.
- Need to install more packages? Change `inside-container.sh`.
